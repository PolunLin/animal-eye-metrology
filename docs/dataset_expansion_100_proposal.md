## Proposed Selection Criteria

| 面向 | 建議凍結的規則 |
| --- | --- |
| 影像來源 | 沿用本機 val2017 與既有註記；COCO image_id、annotation_id、原圖尺寸與 digest 可追溯 |
| 動物條件 | 同圖至少兩隻非 crowd 動物；先不限制物種，不要求兩隻同類 |
| 完整任務資格 | 至少兩隻動物，各自雙眼可見、解剖左右可判，且 v2 範圍在原圖可辨識；才能同時提供兩組雙眼距離及至少一組跨右眼距離 |
| 眼部語義 | 沿用 eye-visible-eyelid-v2：可見眼裂內的眼球表面，加上直接相鄰且能辨認的眼瞼邊緣；擴充新原圖，不改定義 |
| 原圖判讀 | 用原始像素檢查；放大僅幫助操作，不能由插值或對稱性補出不可見邊界 |
| 解析度 | 先不設未驗證的眼高或面積下限；記每眼原圖可見區域寬高、邊界可辨性及不確定原因。低解析度且邊界無法判讀者不列入完整量測集 |
| 審查範圍 | 審核同圖全部非 crowd 動物；對可標的眼睛建立參考，不只保留模型找到的兩隻。無法標者保留狀態與原因 |
| 人工可行性與 GT 驗收 | 篩圖通過只表示值得標註；Mask 完成且 Visible、側別確認、Accepted、Pass 後，才確認完整量測資格 |
| 避免依模型挑樣 | 篩圖與標註時不顯示 YOLO／HRNet／SAM 預測、分數或模型輪廓；不以偵測成功作納入條件 |
| 排除紀錄 | 記不足兩隻、眼不可見、左右不明、邊界不清或來源問題。保留原候選及舊狀態，不自動改成 Pass、不產生假 Mask |
| 分布 | 記錄物種、可見眼框尺寸、姿態、遮擋及光照；不先硬訂十類等額配額。稀少類別不據此宣稱類別泛化能力 |

## Proposed Split Procedure

1. **先凍結標準。** 由負責人確認上述人工資格、v2 新圖適用範圍與保守歷史排除政策。
   在獨立的新審核表篩查候選，記實際 reviewer、規範版本與原因，不改寫 Phase 1 CSV。
   這一步不執行模型。所有用於完整量測的目標與 Mask 都須在查看新預測前確認。
2. **先處理來源相依。** 人工檢查相同／近重複照片與高度相近場景，保存 group_id。
   本提案每組最多選一張進入 100 張；任何組員已有歷史模型或人工紀錄，整組不得進測試。
   每組由合格圖片中選 image_id 最小者作代表；既有三張優先保留為開發代表。
   若既有三張被發現互相近重複，回報衝突再確認，不私自拆組。
3. **先建立暫定測試待標順序。** 對原 380 張中人工篩查通過、且組內無歷史紀錄的代表，
   以 image_id 排序後使用單一 `random.Random(42)` 打亂。前 60 張為暫定待標清單，
   其餘保持同一順序作候補；這時尚未完成 Mask，不稱正式測試集。
   這是有歷史與分組限制的隨機抽樣，不是假定全 471 張無條件隨機抽樣。
4. **建立暫定開發待標順序。** 既有 20247、125405、333069 固定放開發，仍需 37 張。
   已知歷史組中其餘篩查通過代表按 image_id 排序，以同一 RNG 接續打亂，
   依序作開發待標與候補。若不足 37 張，先保留缺額；測試達到 60 張 GT 通過後，
   才從測試來源隊列未使用的尾段依序補開發。不得搶用尚待補足測試的來源或跨組。
5. **依隊列標註與驗收。** 先篩查、再產生待標隊列，僅標這些隊列中的必要圖片，
   不要求先標完整個候選池。因事前定義的不可見、側別不明或 v2 邊界不可判讀而無法
   通過人工 GT 資格時，保存原因並依既定候補順序補入；不得看模型結果後決定替換。
   只有滿 100 張 GT 通過才正式封存 40／60；失敗嘗試仍保留，實際嘗試張數可能超過 100。
   候補耗盡時回報缺額，不放寬邊界、不將 Uncertain 改成 Pass、不自行加入新來源。
6. **封存。** 驗證恰為 40／60、100 個唯一原圖與獨立組，保存原圖／Mask／設定 digest、
   隨機種子、抽樣順序、來源及類別分布。測試 GT 封存，不用於參數選擇；以 40 張完成方法定案後才正式評估 60 張。

這個方案不要求每類等額，避免在尚未知道可標供給時承諾無法達成的配額。
切分後先提交物種及難度分布表，在任何測試推論前檢查；若需改為分層配額，另行確認新規則，
不依測試成績重新抽籤。單純篩圖與標註不是模型驗收；若同一人參與開發及測試標註，
仍不能稱完全盲測。

| 集合 | 數量 | 內容與用途 |
| --- | ---: | --- |
| Development | 40 張 | 含舊 3 張，加新 37 張；研究方法、提示、拒絕輸出與參數 |
| Test | 60 張 | 優先來自原 380 張無已知歷史候選；方法固定後驗收 |
| 合計 | 100 張 | 新增 97 張獨立原圖；雙眼皆合格的兩隻動物只是最低完整任務條件 |

若每張至少兩隻動物通過四眼標註，100 張至少約 400 個有效眼部 Mask；
同圖有更多可標動物時工作量會增加。不能把眼睛、重標版本或多組距離配對算成新的獨立原圖。
模型偵測失敗、空 Mask 或錯誤側別在正式測試中仍保留分母，不以候補圖片替換。
分割、重心與距離仍分開評估，不把「能計算距離」當成量測準確。

## Annotation Quality Proposal

建議 100 張中抽 15 張另作空白盲重標（6 開發、9 測試），不增加獨立原圖數。
抽樣使用獨立 seed 43；測試重標不顯示原 Mask、模型結果或既有量測值。
若有第二位標註者，估計標註者間差異；只有同人重標時，僅估計同人重現性。
重標比較方法與容忍值需在執行前確認，不能從通過與否倒推門檻。

| 方案 | 可回答的問題 | 建議 |
| --- | --- | --- |
| **100 張完整量測條件圖** | 在人工確認可量測條件下，分割與距離誤差如何 | **本提案主方案；先檢查實際供給** |
| 100 張一般多動物圖，保留不可量測狀態 | 對較一般多動物照片的可用率與失敗情形如何 | 研究母體不同，每圖不保證四眼；不自動改採 |
| 擴充到其他 COCO split | 嚴格條件下增加供給 | 本機只有 val2017；新增來源、使用方式及下載另行核准 |

目前供給判定是 **候選母體足夠開始篩選，100 張合格供給尚未驗證**。
主方案至少需要 100 張合格獨立組，且其中至少 60 組來自保守測試來源。
若任一條件不成立，提交實際可用數與缺額，讓負責人決定下一步。

本輪命令：

```sh
.venv/bin/python outputs/dataset_expansion_audit_20261108/inventory_audit.py \
  --output outputs/dataset_expansion_audit_20261108
.venv/bin/python outputs/dataset_expansion_audit_20261108/exposure_audit.py
.venv/bin/python outputs/dataset_expansion_audit_20261108/exposure_audit.py --verify
.venv/bin/ruff check outputs/dataset_expansion_audit_20261108/inventory_audit.py \
  outputs/dataset_expansion_audit_20261108/exposure_audit.py
.venv/bin/ruff format --check outputs/dataset_expansion_audit_20261108/inventory_audit.py \
  outputs/dataset_expansion_audit_20261108/exposure_audit.py
```

建立命令拒絕覆寫既有稽核產物。重現 inventory 時以新的 `--output` 目錄執行；
exposure 可直接 `--verify` 重算。inventory 比對 10 個原有來源，exposure 比對 41 個來源，
兩者各自在執行前後皆無變更。候選原圖雜湊也全部吻合準備紀錄。
另在全新暫存目錄重算 inventory，除實際執行時間外所有欄位相同，CSV 逐位元組一致；
兩份稽核的 47 個原有來源聯集在交付前再次核對未變。
完整性與盤點程式驗證通過；本輪未改核心功能，沒有重跑 pytest、模型推論或新增人工 GT。
正式選圖、近重複人工審查、標註及切分尚未開始。
